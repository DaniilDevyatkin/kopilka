# Эксплуатация Копилки

## Deploy

Практический сценарий для одного VDS описан в `docs/vds-deployment.md`. Команда `bash scripts/deploy-vds.sh` выполняет порядок ниже автоматически.

1. Создать backup PostgreSQL и пользовательских изображений.
2. Собрать неизменяемые `runner` и `migrator` targets из одного `Dockerfile`.
3. Дождаться healthcheck PostgreSQL и выполнить `prisma migrate deploy` отдельным одноразовым контейнером.
4. Запустить новый образ, дождаться HTTP 200 от `/api/health`, затем принять трафик через Caddy.
5. Проверить регистрацию, вход, чтение главной и одну тестовую операцию на отдельном тестовом пользователе.

## Backup и восстановление

- Ежедневно запускать `bash scripts/backup-vds.sh`: он создаёт custom-format `pg_dump`, архив uploaded images и SHA-256 checksums.
- Копировать каталог backup во внешнее зашифрованное хранилище с retention не менее 30 дней. Локальный диск VDS не считается самостоятельной резервной копией.
- При S3 storage включить versioning + lifecycle; база и файлы должны иметь одинаковую политику региона и доступа.
- Ежемесячно выполнять тестовое восстановление в изолированную БД и проверять ledger totals.
- Секреты, session tokens и `.env` в backup исходного кода не входят.

## Rollback

1. Не откатывать применённую миграцию удалением таблиц. Переключить трафик на предыдущий совместимый образ.
2. Для несовместимой схемы выпустить additive forward-fix migration.
3. Восстановление backup допустимо только при потере/повреждении данных и требует остановки записи, фиксации временной точки и сверки ledger после восстановления.

## Инциденты

- При компрометации `SESSION_SECRET`: заменить секрет, удалить все строки `sessions`, повторно развернуть приложение.
- При подозрении на неверный баланс: остановить финансовые мутации, не исправлять cached balance (его нет), сверить `FinancialOperation + LedgerEntry` и резервы отдельным запросом.
- При отказе storage финансовая часть продолжает работать; загрузку изображений временно отключить, метаданные не удалять вручную.
- Логи не должны содержать пароль, raw session token, credential object storage или полный request body.
